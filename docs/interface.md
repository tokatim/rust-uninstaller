# Интерфейс и сценарии

Статус: требования к будущему интерфейсу; визуальный макет пока не создан.
Приложение проектируется как desktop-инструмент для регулярной работы со списком программ.

## Навигация

| Экран | Состав | Этап |
| --- | --- | --- |
| Программы | Поиск, фильтры, таблица, множественный выбор, панель подробностей | M1 |
| План удаления | Выбранные программы, режимы, права, ограничения, запуск | M2 |
| Очередь | Состояние каждой операции, общий ход, пауза/пропуск/отмена следующих | M2 |
| История | Время, target, результат, журнал, экспорт диагностики | M2 |
| Остатки | Дерево кандидатов, доказательства, фильтры, отдельный план очистки | M3 |
| Резервные копии | Состав, статус, размер, восстановление, удаление карантина | M3 |
| Инструменты | Автозапуск, анализ места и экспертные сценарии | M5 |
| Настройки | Язык/тема, сканирование, очередь, исключения, резервирование | M1–M5 |

Недоступные этапы не заполняют UI пустыми неработающими разделами. На M1 нужен
качественный экран программ; навигация расширяется по мере реализации.

## Экран программ

- Верхняя область: поиск, обновление, состояние сканирования.
- Фильтры: источники, scope, архитектура, защищённые записи и поддержка тихого режима.
- Основная таблица: название со значком, издатель, версия, размер, источник.
  Остальные поля доступны как дополнительные столбцы.
- Подробности выбранной строки: происхождение, пути, дата, подпись, режимы и ограничения.
- Панель выбора: количество выбранных, скрытых фильтром и действие просмотра плана.

Даты и размеры форматируются по языку пользователя. Неизвестный размер показывается
как «Неизвестно», оценочный — с отметкой оценки. Сумма выбора не обещает точный
освобождаемый объём. Неизвестная подпись не равна опасной программе.
Данные списка не прыгают и выбор не сбрасывается при фоновом обогащении.

## Основной сценарий

1. Сканирование показывает частичный список и состояние источников.
2. Пользователь ищет и выбирает программы.
3. «Просмотреть план» открывает конкретный список действий, ничего не запускает.
4. План показывает штатное/тихое удаление, необходимые права, проблемы и неизвестные сценарии.
5. «Удалить N программ» подтверждает эту версию плана. UAC появляется только при необходимости.
6. Очередь показывает текущую программу и результат каждой завершённой операции.
7. После удаления предлагается отдельное сканирование остатков.
8. Пользователь просматривает кандидатов и подтверждает отдельный план очистки.

Если uninstall command изменился после просмотра, появляется новый план с
объяснением, а не незаметная замена запускаемого executable.

## Удаление и очистка

У очереди разные действия: «Приостановить очередь», «Отменить оставшиеся» и
поддерживаемая адаптером отмена текущего удаления. Их тексты объясняют эффект.
Завершение процесса принудительно находится в экспертном сценарии и не обещает откат.

Остаток показывает полный путь, тип, размер или unknown, связь с приложением,
уровень уверенности, признаки общих/пользовательских данных и способ резервирования.
Высокая уверенность сама по себе не выбирает пользовательские данные.
Ошибки резервирования видны до удаления; по умолчанию такой объект сохраняется.

## Состояния и сообщения

Обязательные состояния: первый запуск, сканирование, частичные результаты, пустой
список, нет совпадений, ошибка провайдера, отмена скана, устаревший план, отказ UAC,
выполнение, ожидание внешнего окна, требуется reboot, частичный результат,
неподтверждённое удаление, ошибка backup и конфликт восстановления.

Для ошибки сообщаем: что не удалось, затронутые данные и доступное следующее действие.
Код ошибки и технические детали раскрываются отдельно и копируются по запросу.
Пример: «Не удалось запустить удаление. Файл деинсталлятора больше не существует.
Обновите список программ». Текст не обвиняет пользователя.

## Доступность и визуальные правила

- Системная/светлая/тёмная тема; на прототипе проверить Windows high contrast.
- Управление Tab/Shift+Tab, стрелками в списке, Space для выбора; стандартные
  сочетания Ctrl+F и Ctrl+A работают в явной области. Delete не запускает удаление сразу.
- После закрытия диалога фокус возвращается инициатору. Диалог имеет заголовок,
  логичный порядок фокуса и доступное закрытие; блокирующее подтверждение не теряет контекст.
- Иконки действий имеют accessible name; tooltips не заменяют видимые подписи основных действий.
- Состояния различаются текстом и значком. Прогресс сообщается диктору без потока
  уведомлений на каждую найденную запись.
- Текстовый контраст ориентирован на WCAG 2.2 AA; проверять фактические пары цветов.
- При 100/150/200% масштабе и длинных RU/EN строках действия и предупреждения доступны.
- Для больших списков нужна виртуализация с проверкой keyboard/screen-reader поведения.
- Ненужная анимация отключается по reduced motion; обход диска не блокирует ввод.

Шрифты, палитра, отступы, минимальная ширина окна и конкретные компоненты принимаются
в прототипе M0–M1. Сейчас не фиксируется случайная дизайн-система без проверки таблицы.
