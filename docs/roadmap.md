# Этапы разработки

Дата плана: 25 ноября 2026 года. Все этапы реализации пока не начаты. Документационная
основа создана, исходники BCU подключены для переноса; наличие плана не означает
готовность приложения. Сроки уточняются
после M1 на основе работающего прототипа и измерений.

Полный целевой объём: [функциональная спецификация](functional-spec.md).
Каждый этап начинается после выполнения необходимых условий предыдущего. Отдельные
независимые работы можно переставлять без ослабления требований безопасности.

## M0 — воспроизводимый каркас

Результат: desktop-окно запускается на Windows, Rust и UI обмениваются типизированными
данными, проверки воспроизводятся. Версия 0.1 ещё не считается готовой.

- Зафиксировать Rust stable/MSVC, Node LTS, npm и версии библиотек.
- Перед каждой реализацией выбрать существующий модуль BCU по [карте переноса](upstream-reuse.md),
  проверить лицензию и сохранить source commit. Не перепридумывать готовые правила без причины.
- Создать минимальный Cargo workspace и Tauri/React/TypeScript приложение.
- Подключить русские/английские ресурсы, тему и базовую навигацию.
- Создать экран таблицы на синтетических записях с явной отметкой демонстрационных данных.
- Проверить выбор, клавиатуру и отображение большого списка.
- Ограничить Tauri capabilities и CSP; не подключать generic shell.
- Добавить реальные команды lint/typecheck/test/build и Windows CI.

Готовность: чистый checkout собирается по README; приложение запускается; ошибки
команды Rust отображаются корректно; глобальные разрешения не требуются; проверки
проходят. На этой точке подтвердить Tauri/React либо принять пересмотр ADR-0001.

## M1 — инвентаризация, версия 0.1

Требования: INV-01–INV-07, LIST-01–LIST-04, UX-01–UX-03, начальные SET-01/PRIV-01.
Результат: полезный read-only менеджер программ на настоящих данных Windows.

- Реализовать HKCU/HKLM с 32/64 registry views, нормализацию и provenance.
- Добавить partial results, отмену, кэш и фоновое обогащение.
- Добавить поиск, сортировку, фильтры, выбор и подробности.
- Реализовать явный экспорт JSON/CSV.
- Проверить RU/EN, темы, Narrator, scaling и большую таблицу.
- Измерить первый результат, полный скан, память и отзывчивость; принять budgets.

Готовность: scan ничего не изменяет; неполные источники видны; проверены duplicates,
unknown и access denied; нет кнопок, выдающих будущее удаление за готовое. Сравнение
с BCU/Windows используется для изучения расхождений, а не как единственный эталон.

## M2 — штатное удаление, версия 0.2

Требования: INV-08, UN-01–UN-11, HIST-01/HIST-02, расширение SET-01/PRIV-01.
Результат: управляемое одиночное и пакетное удаление с историей.

- Принять ADR на IPC/helper и локальное хранение.
- Реализовать план, подтверждение, свежесть и state machine.
- Добавить MSI, штатный EXE и поддерживаемые quiet adapters.
- Реализовать helper, UAC denied, исходный user scope и независимую проверку targets.
- В первой итерации очередь последовательная. Параллелизм включать отдельной задачей
  после доказанной изоляции adapters; корректность важнее количества одновременных процессов.
- Добавить наблюдение процессов, классификацию exit/reboot, повторный scan.
- Сохранять историю до запуска шага и обрабатывать crash reconciliation.

Готовность: пройдены M2 VM-сценарии, негативные IPC/command tests и проверка потери
связи/хранилища. Отмена не обещает rollback; неизвестные команды не запускаются
через универсальную оболочку. Остатки на этом этапе не очищаются.

## M3 — объяснимая очистка, версия 0.3

Требования: CLN-01–CLN-09, завершение UX/SET/PRIV для этого объёма.
Результат: отдельно просматриваемый план очистки и проверяемое восстановление
поддерживаемых остатков.

- Принять ADR о confidence/evidence, поддерживаемых объектах и формате backup.
- Начать с прямых связей с каталогом и явными записями реестра.
- Реализовать shared/data protection, preview и повторную проверку identity.
- Добавить backup, manifest, restore conflict и управление карантином.
- Обработать full disk, ACL errors, crash, reparse/path substitution.
- Расширять эвристики по одной, с фикстурами ложных совпадений.

Готовность: исходные данные сохраняются при неуспешном backup; защищённые пути и
общие ресурсы заблокированы; restore проверен на VM; нет автоматической очистки
по одному совпадению названия. Полный откат стороннего удаления не обещается.

## M4 — источники, версия 0.4

Требования: INV-09, SRC-01–SRC-04.
Результат: независимые adapters Store/MSIX, Steam, Scoop, Chocolatey и WinGet;
ограниченное обнаружение portable и сиротских каталогов.

Каждый adapter проходит собственный цикл: проверка API/версий → обнаружение →
dedup/provenance → план → штатное удаление → VM-проверка. Scope поддерживается
явно. Недоступный API или отсутствующий менеджер не ломает остальные источники.

Готовность: для каждого источника есть матрица capabilities, воспроизводимые
сценарии и ограничения. Обнаружение кандидата portable не даёт права стереть каталог.

## M5 — расширенные инструменты, версия 0.5

Требования: LIST-05/LIST-06, UN-12–UN-14, CLN-10/CLN-11, SRC-05/SRC-06,
TOOL-01–TOOL-05.

Внутри этапа сначала профили/исключения/CLI, затем обратимое управление автозапуском
и анализ места. Автоматизация чужих окон, force removal, служебные следы, компоненты
и обновления Windows — отдельные задачи с отдельными критериями риска и VM-тестами.
Сценарии пользовательских scripts и другие игровые платформы включаются только
после определения поддерживаемых адаптеров и тестовой среды.

Готовность: каждый экспертный режим отделён от обычного flow; import/CLI не обходят
подтверждение плана и проверки backend. Отключение автозапуска можно восстановить.
Из полного целевого объёма допускается перенос функции только явным изменением
этого плана и спецификации, а не молчаливой отметкой этапа выполненным.

## M6 — стабилизация и выпуск 1.0

Требования: DIST-01–DIST-03 и все обязательные требования M1–M5.

- Подтвердить название и соблюдение уже выбранной Apache-2.0 и лицензий заимствований.
- Провести аудит зависимостей, происхождения кода, данных и ресурсов.
- Проверить portable, установщик, WebView2, миграции и обновление старой версии.
- Организовать Windows code signing и отдельную подпись updater; проверить доступность сертификата.
- Проверить опциональную сеть, приватность и diagnostic export.
- Выполнить полную целевую VM-матрицу и зафиксировать support matrix.
- Подготовить release notes, известные ограничения, поддержку и процедуру выпуска.

Готовность: нет release blockers, данные и backup переживают обновление, release
связан с commit/tag и отчётом. Агент выполняет push и публикацию самостоятельно
по [политике релизов](releasing.md); разрешение владельца уже дано.
