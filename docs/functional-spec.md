# Функциональная спецификация

Версия требований: 0.1 от 25 ноября 2026 года. Статус всех требований ниже —
**запланировано**. Реализованных функций пока нет. Документ задаёт полный целевой
объём, а не состав первого выпуска. При изменении статуса указывать commit и проверку.

Этапы: M0 — каркас; M1 — инвентаризация; M2 — удаление; M3 — остатки;
M4 — интеграции; M5 — инструменты; M6 — выпуск 1.0. Подробности в [roadmap](roadmap.md).
Рабочие версии: 0.1 = M0–M1, 0.2 = M2, 0.3 = M3, 0.4 = M4, 0.5 = M5, 1.0 = M6.

## 1. Инвентаризация

| ID | Требование | Этап | Критерий приёмки |
| --- | --- | --- | --- |
| INV-01 | Читать зарегистрированные программы текущего пользователя и машины | M1 | HKCU/HKLM и обе архитектурные проекции реестра проверены фикстурами; доступ только для чтения |
| INV-02 | Нормализовать карточку программы | M1 | Название, версия, издатель, источник, scope, архитектура, пути и возможности представлены типизированно; неизвестные значения сохраняются |
| INV-03 | Объединять дубликаты с сохранением происхождения | M1 | Одна программа из нескольких источников объединяется по сильным идентификаторам; одинаковое название само по себе не объединяет разные продукты |
| INV-04 | Дополнять сведения в фоне | M1 | Значки, подпись, сведения файла и оценка размера не блокируют первый список; дорогой подсчёт можно отменить |
| INV-05 | Обновлять список и использовать кэш | M1 | Есть ручное обновление; кэш помечен временем и не служит единственным основанием удаления |
| INV-06 | Представлять неполные и защищённые записи | M1 | Скрытые/system component/update-записи помечены; включаемый фильтр не означает разрешение на удаление |
| INV-07 | Показывать ход и ошибки сканирования | M1 | Ошибка провайдера оставляет остальные результаты; виден список недоступных источников; скан можно отменить |
| INV-08 | Перечислять MSI через Windows Installer API | M2 | MSI-записи сопоставлены с реестром по product code без дублей; скан не использует Win32_Product |
| INV-09 | Искать portable-программы и сиротские каталоги | M4 | Скан ограничен выбранными корнями; найденный каталог имеет статус кандидата, а не гарантированной программы |

Для INV-01 проекции открываются через Windows API flags, а не через вручную
составленный путь Wow6432Node. Область «текущий пользователь» не означает обход
чужих загруженных и незагруженных профилей.

## 3. План и удаление

| ID | Требование | Этап | Критерий приёмки |
| --- | --- | --- | --- |
| UN-01 | Формировать план до запуска | M2 | Для каждой записи показаны режим, исполнитель, требуемые права и предупреждения; после подтверждения исполняется именно проверенный план |
| UN-02 | Вызывать штатный EXE-деинсталлятор | M2 | Корректны кавычки, пробелы и Unicode; неверный/отсутствующий executable даёт ошибку до запуска; путь повторно проверен исполнителем |
| UN-03 | Удалять MSI и корректно трактовать коды | M2 | product code валидирован; 0/3010/1641, отмена 1602 и конфликт 1618 различаются; самопроизвольная перезагрузка подавляется поддерживаемыми параметрами |
| UN-04 | Использовать поддерживаемый тихий режим | M2 | Учитываются QuietUninstallString и подтверждённые адаптеры; неизвестному установщику параметры не угадываются; пользователь видит ограничения |
| UN-05 | Планировать пакетное выполнение | M2 | По умолчанию последовательное; MSI и неизвестные конфликтующие операции сериализованы; параллелизм включается лишь для проверенных адаптеров |
| UN-06 | Отслеживать жизненный цикл операции | M2 | Учитываются связанные процессы и timeout; exit code сохраняется; завершение launcher не выдаётся за окончание всего удаления |
| UN-07 | Управлять очередью | M2 | Пауза останавливает запуск следующих элементов; отмена очереди не убивает текущий процесс; пропуск и повтор доступны по правилам адаптера |
| UN-08 | Запрашивать повышение прав | M2 | Отказ UAC — отдельный результат без скрытого повторения; права привязаны к действию, UI остаётся обычным процессом |
| UN-09 | Повторно проверять наличие программы | M2 | После операции выполняется проверка источника; при неясном исходе показан статус «не подтверждено», а не безусловный успех |
| UN-10 | Восстанавливаться после сбоя приложения | M2 | Незавершённые задания показаны при запуске; команды автоматически не повторяются; оставшийся процесс проверяется по PID и времени создания |
| UN-11 | Обрабатывать reboot | M2 | Нужна перезагрузка / уже инициирована различаются; приложение не перезагружает ПК без отдельного действия пользователя |
| UN-12 | Автоматизировать интерактивные деинсталляторы | M5 | Опциональные адаптеры для конкретных проверенных сценариев NSIS/Inno и других; нет универсального нажатия кнопок в чужих окнах |
| UN-13 | Принудительное удаление и исправление битых записей | M5 | Отдельный экспертный сценарий с preview и резервированием; удаление записи не заявляется удалением программы; защищённые объекты блокируются |
| UN-14 | Просмотр запущенных процессов и связанных окон | M5 | Связь доказана путём/идентичностью процесса; завершение требует отдельного явного действия; служебные процессы Windows не выбираются эвристически |

Тихий режим означает отсутствие UI только в пределах возможностей поставщика.
Обычное удаление через неизвестный зарегистрированный EXE допускается после просмотра
плана; shell/scripts/команды без однозначного executable в первой версии блокируются
с объяснением. Расширенные адаптеры добавляются отдельно.

## 4. Остатки и восстановление

| ID | Требование | Этап | Критерий приёмки |
| --- | --- | --- | --- |
| CLN-01 | Искать файловые остатки | M3 | Проверяются подтверждённый каталог установки и ограниченные области AppData/ProgramData; системные корни и общие папки заблокированы |
| CLN-02 | Искать остатки реестра и ярлыков | M3 | Скан ограничен разрешёнными ветками и местами ярлыков; каждое совпадение имеет доказательства связи |
| CLN-03 | Объяснять уверенность | M3 | Показаны основания: явный путь, идентификатор, имя продукта, конфликт с другой программой; уровень не представлен как статистическая вероятность |
| CLN-04 | Проверять совместное использование | M3 | Совпадение с другой установленной программой исключает автоматический выбор; общий каталог издателя не удаляется целиком |
| CLN-05 | Разделять данные и технические остатки | M3 | Документы, сохранения, профили и пользовательские настройки не выбраны по умолчанию; сомнительное содержимое требует отдельного выбора |
| CLN-06 | Показывать отдельный план очистки | M3 | Путь, тип объекта, связь, размер/неизвестно и состояние резервирования видны до подтверждения; scan сам ничего не удаляет |
| CLN-07 | Резервировать и восстанавливать | M3 | Реестр экспортирован с типами и scope; поддерживаемые файлы помещены в локальный карантин; сбой резервирования блокирует удаление объекта по умолчанию |
| CLN-08 | Повторно валидировать объект перед действием | M3 | Изменённые объекты, reparse points и подмена пути отклоняются; ошибка одного объекта отражается как частичный результат |
| CLN-09 | Управлять резервными копиями | M3 | Пользователь видит объём, дату, ошибки и срок хранения; очистка карантина выполняется отдельно, восстановление не перезаписывает новые данные молча |
| CLN-10 | Расширять поиск связанных следов | M5 | Автозапуск, задачи, службы, firewall/COM/другие следы добавляются отдельными правилами с доказательствами и регрессионными тестами |
| CLN-11 | Точка восстановления Windows | M5 | Опциональная попытка с явным результатом доступности/ошибки; её отсутствие не скрывается и не выдаётся за гарантию отката |

При восстановлении файла, поверх которого уже существует новый объект, доступны
отмена и восстановление в другое место. В MVP M3 не поддерживаются произвольные
объекты с неизвестными ACL/streams/reparse-семантикой: они сохраняются без удаления.
Поддерживаемые типы и сохраняемые метаданные уточняются в ADR до реализации CLN-07.

## 5. Источники и интеграции

| ID | Требование | Этап | Критерий приёмки |
| --- | --- | --- | --- |
| SRC-01 | Microsoft Store / MSIX / Appx | M4 | Запрос и удаление через API package deployment; отдельно определены текущий пользователь, другие пользователи и provisioned packages; нет скрытого расширения scope |
| SRC-02 | Steam | M4 | Поддержаны несколько библиотек, app ID и штатный способ удаления; shared redistributables не считаются остатками игры |
| SRC-03 | Scoop и Chocolatey | M4 | Источник и зависимость от установленного менеджера видны; команды выполняет адаптер менеджера; дубль с реестром объединён без потери происхождения |
| SRC-04 | WinGet | M4 | Сопоставление ID/версии/scope проверяется по поддерживаемому интерфейсу; нет хрупкого разбора локализованной таблицы; при неоднозначности требуется preview |
| SRC-05 | Другие игровые платформы, включая Oculus | M5 | Адаптер добавляется при наличии тестовой среды; неизвестные форматы не приводят к удалению каталогов напрямую |
| SRC-06 | Компоненты и обновления Windows | M5 | Экспертный экран отдельно от обычного списка; только поддерживаемые Windows способы; зависимости, необратимость и необходимость reboot показаны |

Интеграция имеет три независимые возможности: обнаружение, удаление и поиск остатков.
Если доступно только обнаружение, интерфейс не показывает неработающее действие.
Проверка API и ограничений соответствующего поставщика обязательна перед каждым адаптером.

## 8. Сквозные правила приёмки

1. Все разрушительные операции проходят через план и границу исполнения из архитектуры.
2. Защищённые и общие ресурсы исключены вне зависимости от фильтров отображения.
3. Отмена, недостаток прав, занятые файлы, отсутствующий helper и ошибки провайдера
   имеют понятные состояния; текущая операция не объявляется откатанной без доказательства.
4. Просмотр и dry-run не запускают сторонние деинсталляторы и не запрашивают UAC.
5. При изменении входных данных после подтверждения план становится устаревшим;
   существенные изменения требуют нового просмотра.
6. Каждая реализованная строка связывается с тестом/VM-сценарием и commit.
7. Ни один экран не обещает функции более позднего этапа как уже доступные.
